inside the `cg-builder` container (repo bind-mounted at `/cg`):

- `--openssl-legacy-provider` is a **node** flag forwarded by the craco launcher
  (`node_modules/@craco/craco/dist/bin/craco.js:16-20` re-spawns
  `node <nodeArgs> <script>`). Needed because react-scripts 5's webpack hashing hits
  OpenSSL 3 restrictions on Node ≥17; the builder runs Node **20.11**
  (`docker/node20/Dockerfile:1`). Should become unnecessary under Vite/esbuild.
- CRA env vars in play and their Vite equivalents: `PUBLIC_URL` → `base`,
  `GENERATE_SOURCEMAP` → `build.sourcemap`, `IMAGE_INLINE_SIZE_LIMIT` →
  `build.assetsInlineLimit`, `HOST`/`PORT` → `server.host`/`server.port`,
  `HTTPS`/`SSL_CRT_FILE`/`SSL_KEY_FILE` → `server.https`.
- `DEPLOYMENT` is **not** a CRA variable — it is read at runtime via a
  `globalThis` indirection (§7.2) and, at build time, only by the craco workbox guard
  (§2.5). It must keep working unchanged.

## 2. `craco.config.js` — complete configuration surface

140 lines; top-level keys `style`, `webpack`, `plugins` only — **no** devServer, babel,
jest or eslint overrides exist.

### 2.1 PostCSS chain

`craco.config.js:8-18` **replaces** the plugin array wholesale with exactly:
`tailwindcss/nesting` → `tailwindcss` → `autoprefixer` (`:11-13`).

**Trap:** a divergent root `postcss.config.js:2-7` also exists with a *four*-plugin
chain (`postcss-import`, then the three above). craco assigns, so `postcss-import` is
**dead** in the current build — but Vite reads `postcss.config.js` by default, so a
naive port would silently re-activate it. `postcss-import` and `postcss-nested` are
declared but unused devDeps (`package.json:144-145`).

### 2.2 Node polyfills

`resolve.fallback` (`craco.config.js:22-39`): `fs tls net path zlib http https crypto
url os crypto-browserify` → `false`; `stream` → `stream-browserify`, `buffer` →
`buffer`, `assert` → `assert` (`:36-38`). Note `stream` appears **twice** — `false` at
`:31` is shadowed by `:36`; do not carry the `false` over.
`webpack.ProvidePlugin({ Buffer: ["buffer", "Buffer"] })` at `:49-51`.

**First-party code needs none of this** — zero `Buffer`/`global.`/node-builtin usage in
`src/` (all `Buffer` grep hits are `ArrayBuffer`s, e.g. `src/data/api/baseConnector.ts:43`).
The polyfills exist solely for transitive deps; strongest drivers found by scanning
installed packages: `@farcaster/auth-kit` (stream/buffer/assert + global `Buffer`),
`@truffle/hdwallet-provider`, `@metamask/eth-sig-util`, `@metamask/sdk`, `ethers@5`.
Matching runtime deps: `assert@^2.0.0`, `buffer@^6.0.3`, `stream-browserify@^3.0.0`
(`package.json:22,25,64`).

### 2.3 ALTCHA alias

`"altcha-widget-element$": "altcha"` (`craco.config.js:44-47`, rationale comment
`:40-43`): loads the altcha bundle under a stub name so its `.d.ts` (which augments
`react/jsx-runtime` and breaks JSX inference with `@types/react` 18) never enters the
TS program. Stub declaration: `src/types/altcha-widget-element.d.ts:1-8`. Single
import site: `src/components/molecules/AltchaWidget/AltchaWidget.tsx:6` (side-effect
import; element created via `React.createElement('altcha-widget', …)` at `:45`).
`altcha` pinned exactly at `2.3.0` (`package.json:21`). The `$` is webpack
exact-match syntax; Vite needs an equivalent `resolve.alias` entry plus the kept stub.

### 2.4 Entries and output

- `webpackConfig.entry` **fully replaced** at `craco.config.js:85-88`:
  `main → src/index.tsx`, `index_cgid → src/index_cgid.tsx`.
- Second HTML via `HtmlWebpackPlugin` (`:64-83`): template `public/index_cgid.html`,
  output `index_cgid.html`, `chunks: ['index_cgid']`.
- `output.filename = 'static/js/[name].[fullhash:8].js'` (`:90`) — **`fullhash`, not
  `contenthash`**, but the override hits only the two **entry** bundles; lazy chunks
  (`chunkFilename`), CSS and asset modules keep react-scripts' `contenthash` naming
  (`node_modules/react-scripts/config/webpack.config.js:221-228,669-670`), so only the
  entry bundles re-bust every build (the SW precache absorbs it either way).
- The `index_cgid` entry is the standalone CG ID/Wallet WebAuthn mini-app
  (`src/index_cgid.tsx:58-60` routes, mount guard `urlConfig.I_AM_CGID === true` at
  `:65`; intended to become its own repo per comment `:21-23`).

### 2.5 Workbox `InjectManifest` patch (largest undocumented piece)

`craco.config.js:95-139` finds the react-scripts-injected `InjectManifest` plugin by
constructor name and **prepends `exclude` rules**: (a) `index_cgid.html` never enters
the precache manifest (`:106-108`); (b) `static/media/*.svg` assets whose source is
`< 5000` bytes are excluded (`:109-119`) — pairs with the post-build SVG prune (§10.1).
**Fail-closed guard:** if no `InjectManifest` is found and `DEPLOYMENT !== "dev"`, the
build aborts with `process.exit(1)` (`:126-133`). Any Vite SW setup must reproduce
both the exclusions and this guard.

The patch **prepends** — CRA's default `InjectManifest` settings must survive the
port: `exclude: [/\.map$/, /asset-manifest\.json$/, /LICENSE/]`,
`dontCacheBustURLsMatching: /\.[0-9a-f]{8}\./`, `maximumFileSizeToCacheInBytes` 5 MB
(`node_modules/react-scripts/config/webpack.config.js:709-717`). Dropping the
`/\.map$/` exclude on the sourcemap-enabled build paths (§1) would put every
sourcemap into the precache.

### 2.6 Dead-but-kept config

Commented-out `BundleAnalyzerPlugin` (writes `../tools/buildStats.json`,
`craco.config.js:52-57`; consumed by `tools/viewBundleSizes.sh:8`) and
`LimitChunkCountPlugin` (`:58-60`). Note: `craco.config.js` itself requires `webpack`
and `html-webpack-plugin` (`:1,4`), both satisfied only **transitively** via
react-scripts — the file must go in the same commit that removes CRA, not after.

- **Yarn 4.1.0** via `packageManager` (`package.json:151`) + repo-vendored
  `yarnPath: .yarn/releases/yarn-4.1.0.cjs`, `nodeLinker: node-modules` (not PnP)

- Installs are plain `yarn` — **no `--immutable`, no offline mirror**; caching is a
  warm `builder-cache` volume (`docker/docker-compose.yml:329-336`,
  `YARN_ENABLE_GLOBAL_CACHE=false`).
- **No `resolutions`/`overrides`** in `package.json`.
- Build tooling sits in **`dependencies`**, not devDependencies: `@craco/craco@7.1.0`,
  `react-scripts@5.0.1`, `typescript@^4.1.2`, `webpack-cli@5.1.4`, all 12 `workbox-*@6.5.4`
  (`package.json:7,53,67,72,73-84`). Also an unused `create-react-app@^5.0.1` (`:27`).
- `eslintConfig` extends `react-app` + `react-app/jest` (`package.json:94-99`) — these

- **The webpack build is the only type-check and the only lint**: react-scripts runs
  `ForkTsCheckerWebpackPlugin` and `ESLintPlugin` (fail-on-error in production) inside
  every build (`node_modules/react-scripts/config/webpack.config.js:719-772`); there
  is no `lint` script and no `.eslintrc*` anywhere — `eslintConfig` is consumed only

- `browserslist` production floors: chrome ≥67, edge ≥79, firefox ≥68, opera ≥54,
  safari ≥14 (`package.json:100-113`) — the reference for Vite `build.target`.

## 4. TypeScript configuration

`tsconfig.json`: `jsx: react-jsx` (`:22`), `target: es5` (`:3`), `module: esnext`,
`moduleResolution: node` (`:17-18`), `isolatedModules`, `noEmit`, `strict`.

- **No `paths` map.** Aliasing is `baseUrl: "src"` only (`:23`), backing
  **~1945 bare-specifier import lines** across `src/` (both quote styles:
  `components/` 827, `context/` 510, `common/` 273, `data/` 189, `hooks/` 80,
  `views/` 44, `util/` 19, `cgid/` 3). Beyond the 8 directory roots there are bare
  specifiers resolving to top-level **files/indexes**: `from 'service-worker'`
  (`src/data/appstate/webSocket.ts:11`), `from 'App'` (`src/views/Home/Home.tsx:29`)
  and directory-index forms like `from "data"`
  (`src/components/templates/CommunityLobby/ChannelManagement/EditChannelForm.tsx:6`).
  This is the single largest mechanical migration item; `vite-tsconfig-paths` covers
  `paths`, not bare `baseUrl`, and per-root aliases miss the file-level specifiers —
  a `baseUrl`-equivalent resolver or a codemod to an explicit `paths` map is safer.
- `include` ends with a trailing comma (`tsconfig.json:34`) — fine for tsc (JSONC),
  breaks strict `JSON.parse` tooling.
- `tsconfig.json:24-26` pins an explicit `types: ["dom-screen-wake-lock"]` array —
  adding `vite/client` is not additive-by-default; the array must be edited (today it
  also suppresses ambient `@types/*` inclusion).
- `src/react-app-env.d.ts:5` (`/// <reference types="react-scripts" />`) is the sole
  source of ambient module types (`*.svg` ReactComponent, `*.png`, `*.css`,
  `process.env` typing) — must be replaced by `vite/client` + a custom SVG declaration.

### 5.1 `src/index.tsx` (main)

### 5.2 `src/index_cgid.tsx` (second entry)

Conventional static imports incl. `import "./index_cgid.css"` (`:19`) and three

### 5.3 HTML templates

Only CRA template variable used: **`%PUBLIC_URL%`** (19× in `public/index.html`, 18×
in `public/index_cgid.html`; no other `%VAR%`). `index.html` carries the `#root` mount
plus 7 portal roots and the `#cg-preview*` loading-screen tree (`:183-206`), an inline
dark-mode bootstrap script (`:168-177`) and a large inline style block; `index_cgid.html`
references a **different manifest** (`manifest_wallet.json`, `:43`) and has no script
tags — though it does carry an inline `<style>` block (`public/index_cgid.html:46`);
scripts are injected by HtmlWebpackPlugin (`craco.config.js:66`).

**Trap:** both HTML entries live **inside `public/`**. CRA copies `public/` verbatim
minus `index.html`, then lets HtmlWebpackPlugin overwrite `index_cgid.html`
(`node_modules/react-scripts/scripts/build.js:69-76,220-224`). Vite's `publicDir` is
copy-verbatim with no overwrite semantics and cannot contain HTML entry files — both
templates must move out of `public/`, which also touches the Tailwind content globs
(`tailwind.config.js:6-7` point at `./public/index.html` / `./public/index_cgid.html`)
and the templates' relative asset references.

### 5.4 `public/` and the font trap

`public/` (37 files): the two HTML entries, `manifest.json` + `manifest_wallet.json`,
`robots.txt`, Google site verification, `logo.svg` (load-bearing — the pre-React
loading screen references it, `public/index.html:194`), `icons/` (17 PNG), `fonts/`
(4 Inter TTF), `audio/` (4 mp3), `video/`, `images/`.

**Trap:** `src/index.css:6,12,18,…` loads fonts via `url('../public/fonts/…')` — CSS
under `src/` reaching *into* `public/`. Webpack processes and hashes these into
`static/media/`; under Vite `public/` is copy-verbatim and `../public/` URLs from
`src/` resolve differently. (`src/index.css:6,12,18` are the only `../public/` references
repo-wide; `src/index_cgid.css` has none.) The Inter fonts ship **twice** today:
hashed into `static/media/` via the CSS *and* verbatim at `/fonts/*.ttf` from the
`public/` copy — and it is the `/fonts/*.ttf` URLs that the SW precaches
(`src/service-worker.ts:75-78`) and nginx's cache rule serves; any font-URL rework
must keep them reachable or the precache manifest breaks (§10.1). Also:
`src/index.css:1-2` starts with two remote Google-Fonts `@import url(…)` (Chivo,
Open Sans, Poppins, Space Mono, Geist Mono) — those are **not** precached and have
no local copy.

## 10. Pipeline couplings to the CRA output layout

### 10.1 `docker/build.sh` flow

`yarn` install (`:63`) → buildId stamp (`:66-72`) → craco build (`:75`) →
`rsync ../build/* nginx/dist/` (`:76`) → **delete all SVGs ≤ 5000 bytes from
`nginx/dist/static/media/`** (`:79-90`) → backend dist assembly with
`cp ../build/index.html backend/dist/` (`:106-109`). Same SVG prune in
`selfhost.sh:80-85`; **absent** from `updateFrontend.sh` (real divergence — frontend-only
updates keep small SVGs). **`IMAGE_INLINE_SIZE_LIMIT` plays no part here** — CRA's SVG rule is `@svgr/webpack`
+ `file-loader` with no inline condition, so every imported SVG is emitted as a
standalone `static/media/` file regardless of size; the inline limit only affects
raster images (avif/bmp/gif/jpeg/png; CRA default 10000, lowered to 5000 here)
(`node_modules/react-scripts/config/webpack.config.js:372-413`). The "SVG hack" is a
**two-way** coupling: the shell prune deletes `<= 5000` bytes, workbox excludes
`< 5000` from the precache (`craco.config.js:116`). The off-by-one is not cosmetic:
an exactly-5000-byte SVG would be precached *and* deleted, and a precached URL that
404s makes `PrecacheController.install()` reject — the SW never activates and PWA
updates silently stop.
`updateFrontend.sh` also does **not** refresh `backend/dist/index.html` — the API
serves the previous shell until `update_backend` runs (pre-existing).

### 10.2 Backend serves and rewrites `index.html`

`srv/api/getRoutes.ts`: reads `/dist/index.html` (`:50`; fatal outside dev `:56-60`),
injects `window.__CG_INSTANCE__` after the literal `<head>` (`:52-54`;
script built in `srv/util/instanceConfig.ts:61-65`), strips default social meta with
regexes (`:62-64`) that assume `property=`/`name=` as the **first** attribute,
double-quoted values and non-empty `content` (the closing slash is optional in the
pattern), splices per-item og/twitter meta before `</head>` (`:65-85`). This is on the **critical path**, not just
share previews: nginx proxies all `/c/…`, `/u/…` deep links to the API
(`docker/nginx/nginx.conf:176-187`). A Vite-emitted `index.html` must keep literal
`<head>`/`</head>` and that meta shape. Today's shipped HTML **is minified** (CRA
runs HtmlWebpackPlugin minification with `keepClosingSlash` in production,
`node_modules/react-scripts/config/webpack.config.js:614-630`, `craco.config.js:68-79`)
and the regexes match that form — minification per se is not the risk; any transform
that **reorders attributes or strips quotes** breaks the regexes *silently* (no
error, just duplicate/leftover meta).

### 10.3 nginx serve-time injection (selfhost only)

`docker/nginx/inject-instance-config.sh` runs as an nginx entrypoint hook **only in the
selfhost image** (`Dockerfile_selfhost:7-8`; prod/dev inject via the API instead).
It seds the `__CG_INSTANCE__` script after the first literal `<head>` in
`/www/index.html` **and** `/www/index_cgid.html` (`:54,62`), idempotency via grep
(`:58-61`), no-op without `CG_APP_URL` (`:23-26`). Assumptions a Vite build must keep:
lowercase attribute-less `<head>`; both HTML files at the **web root under exactly
these names** (pin `rollupOptions.input` keys accordingly). Pre-existing quirk: `&`/`\`
in any `CG_*` value would corrupt the sed replacement.

### 10.4 nginx routing keyed on the layout

Three configs (`nginx.conf` prod / `nginx_dev.conf` / `nginx_selfhost.conf`), all with:

- Cache rule keyed on **`^/(fonts|icons|images|static|audio|downloads)/`**
  (`nginx.conf:202-214`) — Vite's default `assets/` prefix matches **none** of these;
  fall-through goes to `location /` where selfhost's `try_files $uri /index.html`
  (`nginx_selfhost.conf:266`) would serve the SPA shell as `text/html` for a missing
  hashed asset instead of 404. Either keep `assetsDir: 'static'` or extend the regexes.
  No **frontend-static** location gets immutable long-term caching — 24h
  `must-revalidate` is the max there (the `/files/` media proxy does set
  `max-age=604800,immutable`, `nginx.conf:135`).
- `no-cache` on `index.html` + `service-worker.js` + `/e/<id>` (`nginx.conf:217-225`).
- `index_cgid.html` **denied on the main vhost** (`nginx.conf:235-237`); served by a
  dedicated `{CGID_SERVER_NAME}` vhost as `/` → `try_files /index_cgid.html =404`
  (`nginx.conf:277-309`); dev config serves it by path instead
  (`nginx_dev.conf:233-240`).
- Cross-origin-isolation shells `/enable-cross-origin-security` /
  `/disable-cross-origin-security` with COOP/COEP headers (`nginx.conf:239-259`),
  also precached by the SW.
- `asset-manifest.json` has **no consumer anywhere** — droppable.
- Dev stack: craco dev server on `:3000` and nginx-served build on `:8000/:8001`
  coexist (`docker/docker-compose.yml:274-276`).
